# Phone network

Pairing QR (spec rev 3):

```
readersync://pair?v=1&host=<ip>&port=8788&token=<t>&server=<serverId>
```

The readersync service on the Mac mini listens on **8788**. Port 8787 belongs to another service. The phone does not bake in a host or a port. `parsePairingUrl` requires both, and the HTTP client uses that origin (`http://<host>:<port>`) for every later request. `SYNC_PORT` (8788) is only the documented example.

The credential from `POST /v1/pairing/redeem` is stored with `expo-secure-store`. The outbox snapshot, including a batch written before it is sent, is stored in AsyncStorage under `readersync.state`, the same store the shelf uses.

## Android cleartext

Tailscale HTTP is cleartext. When the native Android project is generated, add a `networkSecurityConfig` that allows cleartext for the Mac mini's Tailscale address only. Do not set `android:usesCleartextTraffic="true"` on the application.

`100.97.87.111` is that host today. The config is still a single-host exception, not a port exception: Android matches the host, and the app will only call the host from the QR.

```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
  <base-config cleartextTrafficPermitted="false" />
  <domain-config cleartextTrafficPermitted="true">
    <domain includeSubdomains="false">100.97.87.111</domain>
  </domain-config>
</network-security-config>
```

Point the debug and release manifests at it with `android:networkSecurityConfig="@xml/network_security_config"`. This file is not added under `android/` yet. `android/` is generated by prebuild and gitignored.
